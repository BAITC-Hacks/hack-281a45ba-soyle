# Демонстрация Soyle за 5 минут

Перед выступлением запустите `npm run dev`, откройте адрес из терминала и подготовьте этот файл для копирования. Сохраните текущую работу через «Как это работает» → «Скачать копию». Для чистого старта нажмите «Восстановить демоданные» и подтвердите действие. В течение всей демонстрации используйте тот же браузер, адрес и одну вкладку.

## 0:00–0:30 — Зачем нужна платформа

Откройте «Каталог задач». Покажите карточки, уровни готовности и фильтр по теме.

Реплика: «Бизнес описывает потребность, платформа помогает подготовить понятную задачу, а команды предлагают подходы. Решение о сотрудничестве и приемке остается за бизнесом».

Поясните, что опубликованные задачи с низким рейтингом тоже доступны командам. Рейтинг показывает полноту описания.

## 0:30–1:25 — От короткого описания к уточнениям

Выберите роль «Бизнес» и нажмите «Разместить задачу». На шаге «Описание» вставьте:

> Хотим лучше учитывать остатки в небольшом магазине. Сейчас ведем таблицы вручную и иногда поздно замечаем, что товар закончился.

Нажмите «Получить вопросы». Покажите не менее трех уточняющих вопросов, пример ответа под вопросом и обозначение демонстрационного режима. Пример объясняет структуру ответа и сам ничего не заполняет.

Реплика: «Сейчас выбран серверный mock-режим. Первый запрос анализирует описание и возвращает вопросы. Настоящий режим использует OpenAI с тем же контрактом; для этой демонстрации ключ не нужен».

Ответьте на отображенные вопросы текстами из таблицы ниже, затем нажмите «Сформировать карточку». Второй запрос передает исходное описание и ответы и возвращает структуру задачи. Покажите, что неизвестные сведения остались пустыми. Карточку можно редактировать; под каждым полем раскрывается «Пример ответа».

## 1:25–2:35 — Карточка, рейтинг и публикация

Для примера используйте следующие сведения:

| Поле | Текст для вставки |
| --- | --- |
| Название | Учет остатков магазина «Демо Маркет» |
| Тема или отрасль | Ритейл |
| Контекст | Один магазин, 300 наименований. Остатки ведем вручную в таблицах. |
| Потребность | Нужно замечать низкие остатки до того, как товар закончится. |
| Целевые пользователи | Продавец и управляющий магазина. |
| Данные и материалы | Синтетический CSV: артикул, наименование, остаток, минимальный запас. |
| Ограничения | Две недели, работа в браузере, без интеграции с кассой. |
| Ожидаемый результат | Прототип панели остатков с фильтром товаров ниже минимального запаса. |
| Критерии успеха | На тестовом наборе панель находит все позиции ниже порога; управляющий открывает их за два действия. |
| Контакт | demo-store@example.com |
| Формат взаимодействия | Два коротких созвона в неделю и обратная связь по прототипу. |

Сначала нажмите «Подтвердить сведения» для частично заполненной карточки и покажите расшифровку рейтинга. Дополните данные и критерии успеха, подтвердите обновленные сведения и покажите рост баллов. Полностью заполненная и подтвержденная карточка получает 100.

Реплика: «После моего подтверждения backend считает баллы по фиксированной формуле. LLM рейтинг не рассчитывает. Владелец проверяет содержание, а перед публикацией backend проверяет подтверждение еще раз».

Нажмите «Опубликовать задачу» и найдите ее в каталоге по названию. Покажите сортировку по рейтингу или фильтр уровня «Приоритетная».

## 2:35–3:25 — Предложение команды

Переключитесь в роль «Студент» и выберите профиль «Steppe AI». Откройте опубликованную задачу. Заполните форму и нажмите «Отправить предложение»:

| Поле | Текст для вставки |
| --- | --- |
| Идея | Панель остатков с подсветкой дефицита и поиском по артикулу. |
| План | Уточним CSV, соберем таблицу и фильтры, проверим на тестовом наборе, покажем управляющему. |
| Срок | 14 дней |
| Ссылка на прототип | https://example.com/demo-inventory |

Ссылка синтетическая; открывать ее во время демонстрации не требуется. В «Моих откликах» покажите отправленное предложение.

## 3:25–4:20 — Решение бизнеса и баллы

Вернитесь в роль «Бизнес», откройте «Отклики команд» и найдите предложение к новой задаче. Нажмите «Выбрать команду».

Реплика: «Представитель бизнеса может выбрать одну, несколько или ни одной команды. Платформа не назначает исполнителя автоматически».

Нажмите «Подтвердить этап» у выбранной команды. Покажите +50 баллов в разделе «Команды» и статус «Первый этап подтверждён» в отклике. Повторное начисление за этот этап недоступно.

Поясните: «Это демонстрация ручной приемки этапа. В реальной работе бизнес сначала проверяет результат команды».

## 4:20–5:00 — Сохранение и честные ограничения

Перезагрузите страницу и покажите, что задача и решение сохранились. При необходимости снова выберите нужную роль.

Откройте «Как это работает» и нажмите «Скачать копию»: задачи, отклики и прогресс выгружаются в JSON для переноса или восстановления. Неотправленный текст формы в общую копию не входит.

Реплика: «MVP проводит обе стороны через полный сценарий. Backend выполняет два этапа AI и считает готовность, а задачи и отклики пока хранятся в браузере. Здесь включен явно обозначенный mock. Для совместной работы с разных устройств еще нужны общая база и авторизация. Исходный код, правила рейтинга, AI-контракт и проверки находятся в репозитории».

Дополнительная проверка вне пяти минут: откройте опубликованную задачу с готовностью «Черновик» (0–39) в роли команды и отправьте отклик. Он проходит независимо от рейтинга; уровень готовности и статус публикации различаются.
